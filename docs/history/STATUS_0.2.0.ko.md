## CPU/NPU 결과와 해석

실제 음악 정책은 자체 규칙을 모방 학습한 16→32→6 MLP이며 사람의 평가로 학습하지 않았습니다. 동일한 32개 입력에서 OpenVINO CPU와 NPU 출력 최대 절대 차이는 0.00055206입니다. 실제 NPU 실행과 수치 일치는 검증했으나, 이 버전의 음악 정책에 대한 통제된 지연 분포·CPU 사용률·전체 시스템 전력 비교는 수행하지 않았습니다. UI의 추론 시간은 마지막 호출 시간이며 중앙값이 아닙니다.

초기 비학습 진단용 16→32→8 MLP의 별도 100회 측정에서는 CPU 중앙값 0.03415 ms, NPU 0.68695 ms였습니다. 이는 현재 음악 정책의 벤치마크가 아닙니다. 작은 그래프에서는 NPU가 빠르거나 전력이 낮다고 가정하지 않습니다. 음악적 우월성·팬 소음 감소 효과는 측정하지 않았습니다.

## 발견·해결

- 주기적 중단: 고장이나 버퍼 고갈이 아니라 30초마다 예약된 3.5초 무음 재보정이 원인이었습니다. 기본 연속 재생으로 바꾸고 주기 보정은 명시적 opt-in으로 전환했습니다.
- NPU 미사용: 기존 앱은 CPU 절차적 음악만 사용했습니다. 실제 음악 정책 모델·전용 추론 스레드·합성 파라미터 연결·CPU 폴백을 추가했습니다.
- DLL 로드: 혼합 경로 구분자가 포함된 LoadLibraryEx 경로를 정규화한 절대 경로로 수정했습니다. 전역 PATH는 변경하지 않았습니다.
- 첫 캡처의 Xrun: 시작 Xrun을 치명적 오류로 처리하던 문제를 수정했습니다. Xrun/RealtimeDenied는 계수하고 장치·권한·경로 오류는 안전 정지합니다. 시작 Xrun 1회가 사라졌다고 주장하지 않습니다.

내장 장치는 F32 stereo 48 kHz, 지원 버퍼 480프레임으로 열거됐으며 분석은 mono입니다. 실제 주변 입력에서 신뢰할 수 있는 팬 주기성을 검출하지 못한 경우 fan_hz=0을 유지합니다. 캡처 성공을 팬 식별 성공으로 해석하지 않으며 Raw/AGC/노이즈 억제의 영향은 후속 조사 대상입니다.
