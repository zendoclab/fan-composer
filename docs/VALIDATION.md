# 검증 절차와 완료 판정 — 0.2.0

빌드, 디지털 데이터 처리, 물리적 장치 입출력, 사람이 듣는 음향 품질을 각각 기록합니다. 성공하지 않은 항목은 미검증으로 남깁니다. 현재 결과는 STATUS.md와 NPU_CONTINUITY_0.2.0.md를 참조합니다.

## 자동 검증

- FFT 2048/4096 고정 467 Hz 오차 < 1 Hz, 하모닉 신뢰도와 광대역 노이즈 오검출 억제.
- 주파수 급변·상승 추적, 7개 합성 팬, 무음·NaN 입력.
- 세 모드 유한 출력·피크 제한·재현성·서로 다른 출력, 시작/정지 페이드와 모드 전환.
- 기본 연속 재생 및 수동/주기 보정 스케줄, 세 모드 각 100초 가상 시간의 기존 30/60/90초 중단 회귀 방지.
- 콜백 DSP 및 파라미터 전달의 초기화 후 메모리 할당 0.
- 실제 마이크 캡처와 volume=0 출력의 프레임 수·레이트·스트림 오류·quiet 상태를 확인. 원시 마이크 데이터는 저장하지 않음.
- NPU는 열거 / 컴파일 / 시험 추론 / 실제 실행 장치 / 음악 정책 결정 횟수를 구분. 자체 규칙 모방 모델이며 진단 난수 그래프와 구분.
- NPU 사용 불가 주입으로 같은 선택 경로의 실제 OpenVINO CPU 폴백을 확인. 물리적으로 NPU가 없는 PC 검증과 구분.

현재 자동 테스트 19개가 통과했습니다. 포터블 45초 무음 입출력에서 실제 NPU 결정 45회, 시작 4초 이후 quiet=true 0회, fault/큐 손실/콜백 처리 예산 초과 0이며 시작 Xrun 1회가 기록됐습니다. 무음 입출력은 청취 품질 검증이 아닙니다.

## 사용자 청취 테스트

1. 내장 스피커를 명시적으로 선택합니다. Start 전에 마이크 수집과 출력이 OFF인지 확인합니다. Windows 전체 볼륨은 사용자가 정하며 앱이 변경하지 않습니다.
2. Start 후 3.5초 보정이 끝나면 세 모드를 각 60초 이상 들어봅니다. Auto quiet calibration은 OFF로 두고 이전 30초 경계의 중단, 클릭·울림·과한 음량이 없는지 기록합니다.
3. 상단 Music policy의 실제 NPU 표시와 NPU 결정 카운터 증가를 확인합니다. 낮은 주기의 작은 모델이므로 작업 관리자 사용률이 높을 필요는 없습니다. 폴백이면 표시된 원인을 기록합니다.
4. 팬 속도가 바뀌면 Calibrate를 눌러 3.5초 재측정합니다. 기본적으로 재생 중 팬 특징을 유지하므로 자동 연속 추적이나 음향 AEC로 해석하지 않습니다.
5. Volume=0, Peak cap 변경, Stop, 창 종료를 확인합니다. Stop 후 마이크 표시가 꺼지는지 확인합니다.
6. 다른 음악·대화 중 감쇄 옵션을 비교합니다. 현재 휴리스틱은 음성 탐지기가 아니므로 미탐/오탐을 기록합니다.
7. 장치를 분리했을 때 안전 정지와 명시적 재시작을 확인합니다.
8. 내장 마이크의 Windows 오디오 향상/AGC 설정을 기록하되 앱이 시스템 설정을 임의로 변경하지 않습니다.
9. 1시간 / 8시간 사용 시 callback over-budget, queue drops, stream fault, 메모리, 환경을 기록합니다. over-budget은 실제 WASAPI underrun 카운터와 다릅니다.

사용자는 0.1.1의 세 모드를 들었고 대체로 괜찮다고 평가했습니다. 0.2.0 변경 후 실제 청취와 장시간 사용은 아직 별도 검증하지 않았습니다.

## 쾌적성 실험

팬 상태를 최대한 고정하고 조건 A 팬만 / B 고정 ambient / C FFT 적응 / D NPU 적응을 무작위 순서로 제시합니다. 현재 NPU 정책 실행은 구현됐지만 통제된 A/B 실험용 조건 고정·순서 관리 도구는 아직 없습니다. 모델은 규칙 모방이므로 D가 C보다 낫다고 가정하지 않습니다. NPU 실행 자체의 전력·팬 소음 영향도 기록합니다.

각 조건의 불쾌감·집중 방해·자연스러움·화성·음량 부담·장시간 사용 의향을 1–7로 평가합니다. 전체 음량 변화와 음악적 조화 효과를 구분하며 데이터가 부족하면 효과를 단정하지 않습니다.
